# Sample datasets

Small, seeded datasets for development, tests and the Wave 2 plot work: every chart in
[Plots.md](../Plots.md) can be drawn from one of these files. The whole folder is about 2.2 MB
(limit: 5 MB).

All files except `sales.csv` are generated by [`scripts/gen_samples.py`](../scripts/gen_samples.py)
(`uv run python scripts/gen_samples.py`; add `--check` to verify the committed files are up to
date). Each file has its own seeded random stream, so changing one generator never moves another
file's numbers. The data is synthetic and the reference tables (countries, US states, cities) are
rounded approximations for illustration, not official statistics. `sales.csv` is hand-kept and is
never rewritten (tests use it).

`frontend/e2e/samples.spec.ts` imports every file through the real import endpoints and checks row
counts, column names, semantics and nulls, so a new file must be added there too (a test fails if a
file in this folder is not covered).

## Files

Column types are what the importer infers. "Plots" uses the `PlotType` keys.

### Business, web and composition

| File | Rows | Columns | Notes and intended plots |
|---|---|---|---|
| `sales.csv` | 500 | `order_id`, `order_date` (date), `region`, `product`, `channel`, `units`, `unit_price`, `sales` | The tests' fixture. `bar`, `horizontal_bar`, `grouped_bar`, `stacked_bar`, `pie`, `donut`, `line`, `area`, `stacked_area`, `percent_stacked_bar`, `mosaic`, `marimekko` (region x product x channel), `error_bar` |
| `web_traffic.csv` | 10,000 | `timestamp` (**time-zone-aware**, a different UTC offset per row), `country`, `device`, `channel`, `page` (**~400 distinct**, Zipf-distributed), `load_ms`, `size_kb`, `bounced` (bool), `revenue` (**about 95% null**) | Request log over 45 days. | `customers.tsv` | 3,000 | `customer_id`, `company` (**~1,800 distinct**), `city` (**~300 distinct**), `country_iso3`, `segment`, `signup_date`, `age`, `income`, `credit_score`, `last_purchase`, `satisfaction` (1-5), `notes` | **TSV.** Nulls in six columns, quoted text with commas and quotes in `notes`. `lorenz` and `ecdf` (income, log-normal), `histogram`, `box` by segment, `treemap` of company counts |
| `sales_hierarchy.csv` | 20 | `region`, `category`, `product`, `revenue_k`, `growth` | Three-level tree: `treemap`, `sunburst` |

| `funnel.csv` | 6 | `stage_order`, `stage`, `users` | `funnel` |

### Import-path coverage

These exist mainly to exercise the importers; the data itself is also usable for charts.

| File | Format | What it tests |
|---|---|---|
| `customers.tsv` | tab-separated | TSV detection, quoting, nulls |
| `survey_unicode.csv` | UTF-8 **with BOM** | Unicode column names (`名前`, `Größe (cm)`, `Café visits / week`, `prix €`, `Satisfaction ★`), spaces and parentheses in names, 6-20% nulls per column |
| `ventes_europe_cp1252.csv` | CSV in **Windows-1252** (not UTF-8) | Transcoding; accents and the euro sign in the header and values; `dd/mm/yyyy` dates |
| `quarterly_report.xlsx` | Excel, **two sheets** | `Revenue` (48 rows, real Excel dates, a formula column) and `Headcount` (8 rows, one column per quarter: a natural `unpivot` example). Import each sheet separately |
| `products.json` | JSON **array** | 120 records with a nested object (`dimensions`) and a list (`tags`); null `rating` |
| `events.ndjson` | **NDJSON** | 2,000 events, ISO timestamps with `Z`, null `value` |
